# acceptance_audit

Primary connection: RTLRewriter, ICCAD 2024, evaluation and ablation sections,
https://arxiv.org/html/2409.11414v1. This bounded engineering audit adapts
verification-before-PPA evaluation. It is not a paper algorithm or a completion
certificate.

The operation scans every modular JSON declaration and every study envelope in
the supplied evidence tree. It retains failures, checks generated/core/fixture
source identities, binds correctness evidence, validates cycle contracts and
repeated physical conditions, and counts substantial configurations by family.
Declared cases without complete verified metrics keep the all-case geometric
benefit undefined. No failed candidate is assigned a neutral value or removed.
The worst complete benefit across retries is used; every observation is retained.

A 50-entry inventory binds registry implementations, experiment READMEs, primary
paper references and test source files. Structural checks do not prove semantic
independence, PPA-purpose classification, actual exercise or negative-test quality.
These remain explicit review items, alongside historical timing-report coverage,
predeclaration, full historical inventory, documentation and PR/usage state.
completion_claim_supported always remains false: the calling agent must perform
those independent reviews before claiming the user goal is complete.

Run `python exp/tool-exploration/exp-tool-50-rtlrewriter/run.py`. Incomplete
acceptance is an expected audit result, not permission to hide missing cases.
Additional freshly exported study files can be passed with repeated --study.
The tool does not synthesize, rerun proofs, merge, or change acceptance thresholds.
